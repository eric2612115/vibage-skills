# Coverage box — reader experiment

Git-safe index for the one behavioural claim this mechanism makes. Full judge
transcripts live in agent chat only; raw artifacts were at
`/tmp/reader-exp-1785002313/` (`SCOREBOARD.json`, `manifest.json`, `truth/`).

## What was tested

The claim is **not** "the agent writes fewer overclaims". It is: *a sentence
claiming full coverage, sitting under `repos_dug: 1 / 9`, is self-refuting **to the
reader***. That is a claim about reader inference, so the reader is what was
measured.

| Field | Value |
|-------|-------|
| Claim | `COVERAGE_BOX_READS_OK` — the box makes dig coverage readable from the report alone |
| Run id | `reader-exp-1785002313` |
| Design | Same report content in two versions: **A** = with `vibage_coverage_v1` box, **B** = box removed, **prose otherwise byte-identical** |
| Scenarios | 8 pairs, all "bad news" hubs: `repos_dug ≤ 1/3` of discovered, 掃透=NO, ≥1 `missing-env-config` |
| Judges | 24 clean judges (12 per arm), no hub access, not told the purpose |
| Ground truth | Computed directly from each hub |

## Result

| Question | A (box) | B (no box) |
|----------|---------|------------|
| Q1 how many repos were dug — accuracy | **100%** | **0%** |
| Q1 answered "cannot tell" | **0%** | **100%** |
| Q2 was a full sweep proven (truth: NO) | 100% | 100% |
| Q3 are there unconnected externals / gaps | 100% | 100% |
| Mean confidence "covers the whole system" (0–10) | 1.4 | 1.9 |
| Overconfident (conf ≥7 while dug < 1/3) | 0% | 0% |

**Model confound checked and excluded.** Arm/model assignment was unbalanced
(A: 8 grok / 4 composer; B: 4 grok / 8 composer), but the effect holds *within*
each model — grok A 8/8 vs B 0/4; composer A 4/4 vs B 0/8. Ground truth varied
across pairs (dug 1–2, discovered 5–12), so judges were not scoring a constant.

## What this shows

The null hypothesis "the box makes no difference ⇒ A ≈ B" is **falsified on Q1**.
Without the box, no judge could state how much was actually dug — every one of
them said so plainly rather than guessing. With the box, every judge got it right.

The mechanism is **bounded reading**, not **blocked writing**.

## NOT claims

- ≠ chat has a firewall (chat remains uninstrumented; see `docs/HONESTY-SURFACES.md`)
- ≠ authors write fewer overclaims — a separate 12-agent writer panel had **no
  power** to test this (zero baseline in the control arm) and is not evidence
  either way
- ≠ the box improves 掃透 or gap judgement — Q2/Q3 were 100% in **both** arms;
  the prose already carried enough. Do not claim an increment here
- ≠ the box reduces overconfidence — both arms were 0%; these judges were
  conservative, so there was nothing to reduce
- ≠ validated on the live 17-repo DefiStrategy — these were synthetic hubs
- ≠ semantic understanding of any kind
- ≠ letter B ≠ C′ Proven-green ≠ Gate B (CONFIRM)
- `COVERAGE_BOX_OK` (the script token) is a different thing entirely: it means the
  numbers match the hub, not that anyone read them

## How to re-run

1. Build ≥8 hubs satisfying the bad-news predicate (dug ≤ 1/3, 掃透 NO, ≥1 missing-env)
2. Produce A/B report pairs — remove only the coverage box, change no prose
3. Dispatch clean judges, one version each, four questions, no hub access
4. Score against hub-computed truth; **report the within-model breakdown**, not
   just the pooled number
